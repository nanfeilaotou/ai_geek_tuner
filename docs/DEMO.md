# AIGeekTuner 演示脚本（约 5 分钟）

> 演示前检查：已在设置中配置并激活可用的 AI Provider；使用 Ollama 时确保服务正在运行并已执行 `ollama pull qwen3:8b`，应用为 Release 发布目录下的 exe。

## 1. 首页（30 秒）

- 一句话：这是一个本机采集与 SafetyGuard、Provider 可配置的 AI 硬件故障诊断工具；是否出网取决于当前 AI Provider。
- 指一下左侧导航与底部版本号。

## 2. 硬件信息（1 分钟）

- 展示真实采集：CPU / GPU / 内存（容量·厂商·频率）/ 磁盘 / 系统。
- 点击「刷新实时状态」：温度、功耗等来自 LibreHardwareMonitor。
- 强调：读不到的字段显示「未检测到」，程序不会编造数据。

## 3. 设置（1 分钟）

- 服务地址默认 `http://localhost:11434`，可改局域网地址。
- 「刷新模型」拉取已安装模型；也支持手动输入未来要安装的名字。
- 点「测试连接」演示三态：就绪 / 模型缺失 / 无法连接。
- 提一句：保存后下一次诊断立即生效，不需要重启。

## 4. AI 智能诊断（1.5 分钟）

- 粘贴一段公开示例日志（见下方 Demo Log）。
- 可在「用户补充描述」加一句现象说明。
- 点「开始诊断」：右侧三个阶段卡展示进度。

## 5. 诊断报告（1.5 分钟）——重点

- **事实证据**：只引用日志/硬件里真实存在的内容。
- **AI 推测**：带“可能”“需要验证”措辞的候选原因。
- **置信度** 与 **风险等级**。
- **SafetyGuard**：说明本地规则会拦截危险电压/禁用保护类建议。

## 6. 日志管理（0.5 分钟）

- 展示记录含模型、耗时、成功/失败；点开可回看报告；支持导出 Markdown。

# 常见答辩问题

### 为什么不用云 API？

使用本地 Provider 时可离线演示且无需云端 API Key；使用云端 Provider 时，诊断上下文会发送至所配置的服务。诊断场景的日志本身敏感。

### 怎么防止模型胡编？

五层防线：结构化 Prompt 与 source block 划定证据边界 → Fact 的 sourceId/sourceQuote 确定性校验 → 只允许 JSON 输出并强类型校验 → 事实/推测分层展示 → 本地 SafetyGuard 规则拦截危险建议。程序自身也不给模型提供温度电压等未采集数据。

### 模型输出的 JSON 坏了怎么办？

Provider 的结构化 JSON 模式约束输出；解析器容忍围栏/噪声并强校验字段；解析或 grounding 失败时自动携带简短错误反馈做**一次**修复重试；仍失败则归类报错，不展示无证据事实。

### Ollama 没开会怎样？

开始诊断前有 readiness 预检：离线或模型缺失都会得到明确中文提示，界面不会崩溃也不会假死。

### 为什么不用数据库？

当前数据量下 JSON 文件更简单：索引+详情分离、原子写入、损坏自动备份重建已经覆盖需求。

### 为什么没用依赖注入框架？

项目规模下手写 Composition Root 更直接可控；接口边界（IAiService 等）依然清晰，未来引入成本低。

### AI 会诊错吗？

会。所以工具定位是辅助诊断：用 confidence 表达确定程度、强制区分事实与推测、给出验证步骤而不是结论性维修指令。
